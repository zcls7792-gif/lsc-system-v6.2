# 屏幕阅读器人工测试清单 (NVDA / VoiceOver)

> 生成时间: 2026-08-30T15:19:06.930Z
> 测试标准: WAI-ARIA 1.2 + WCAG 2.1 AA
> 前置条件: 在真机/模拟器上部署 LSC 系统，启动屏幕阅读器

## 平台管理后台 [platform-admin]

- **URL**: `http://localhost:18910/platform-admin/index.html`
- **屏幕阅读器**: NVDA (Windows)
- **快捷键**: Ins+B (朗读全文), Ins+Tab (下一个焦点), Ins+F7 (标题列表), Esc (关闭弹窗)

| 编号 | 检查项 | 操作步骤 | 预期结果 | 实际结果 | 通过 |
|------|--------|----------|----------|----------|------|
| SR-01 | 页面加载朗读 | 打开页面后，屏幕阅读器应自动朗读页面标题和主要地标。验证是否朗读了"链盛通LSC"标题及"导航""主内容"等地标。 | 朗读页面标题 + landmark 角色 | | ☐ |
| SR-02 | 跳过链接 | 页面加载后按 Tab，第一个焦点应为"跳到主内容区"链接。按 Enter 激活，焦点应跳转到主内容区。 | 首个 Tab 焦点 = skip-link → Enter → 焦点到 #view/#content | | ☐ |
| SR-03 | 导航地标朗读 | 使用屏幕阅读器地标导航 (NVDA: Ins+D / VO: VO+U 选 landmark)，应列出"导航""主内容""顶部操作栏"等地标。 | 地标列表包含 navigation + main/region | | ☐ |
| SR-04 | 导航项朗读 | Tab 遍历每个导航项，验证朗读名称+角色。当前激活项应朗读"当前页面"。带 badge 的项应朗读待处理数量（通过 sr-only）。 | 每个 nav-item 朗读名称 + "按钮"；激活项朗读"当前页面"；badge 朗读数量 | | ☐ |
| SR-05 | 搜索框 | Tab 到搜索框，验证朗读关联标签（如"搜索商家、订单或用户 ID"）+ "编辑框"。 | 朗读 aria-label 文本 + "编辑框" | | ☐ |
| SR-06 | 主题切换按钮 | Tab 到主题切换按钮，验证朗读"切换主题 按钮"。点击切换后状态变化应可被感知（data-state 属性变化）。 | 朗读"切换主题 按钮"；三态切换后 data-state 更新 | | ☐ |
| SR-07 | 弹窗打开 | 触发弹窗（如点击商家详情/处罚操作），验证：(a) 朗读弹窗标题 (b) 焦点进入弹窗 (c) Tab 键在弹窗内循环。 | 弹窗打开时朗读标题 + 焦点进入 + Tab 循环 | | ☐ |
| SR-08 | 弹窗关闭 | 按 Esc 或点击关闭按钮关闭弹窗，验证：(a) 弹窗消失 (b) 焦点返回触发弹窗的元素。 | Esc → 弹窗关闭 + 焦点返回触发按钮 | | ☐ |
| SR-09 | 双人审批弹窗 | 触发双人审批弹窗，验证：(a) 朗读"双人审批"标题 (b) 两个输入框朗读标签"第一管理员签名""第二管理员签名" (c) 输入后状态文本变化被朗读。 | 标题朗读 + 输入框标签 + 状态变化 live region 朗读 | | ☐ |
| SR-10 | 表单标签 | Tab 遍历所有表单输入框，验证每个输入框朗读关联的 label 文本。 | 每个 input 朗读 label + "编辑框" | | ☐ |
| SR-11 | Tab 顺序 | 从页面顶部按 Tab 顺序遍历，验证焦点顺序符合视觉阅读顺序（从上到下、从左到右）。 | Tab 顺序 = 视觉顺序，无跳跃 | | ☐ |
| SR-12 | 图片/图标替代文本 | 使用屏幕阅读器浏览图片和图标区域，验证：装饰性图标不朗读（aria-hidden），有意义图片朗读 alt 文本。 | 装饰图标静默；信息图片朗读 alt | | ☐ |
| SR-13 | 档位/信用分卡片 | 在移动端首页浏览商家卡片，验证：档位标签朗读"档位X"，信用分朗读"信用XX分，XX状态"。暂停/关闭的卡片朗读"核销权限受限"。 | 档位+信用分+状态均被朗读；禁用卡朗读受限提示 | | ☐ |
| SR-14 | 底部导航 | Tab 到底部 Tab Bar，验证：每个 Tab 朗读名称 + "按钮"，当前页朗读"当前页面"。 | Tab 项朗读名称 + 角色；激活项朗读"当前页面" | | ☐ |
| SR-15 | 动态内容更新 | 触发动态内容更新（如通知面板展开、审批状态变化），验证屏幕阅读器是否朗读更新内容。 | 状态变化被朗读（需 aria-live 或 role=status） | | ☐ |

## 已知限制

- 自动化审计 (audit-screenreader.js) 覆盖 DOM 级 ARIA 标记，无法覆盖屏幕阅读器实际朗读行为
- 人工测试需在真实硬件上使用 NVDA (Windows) 或 VoiceOver (iOS/macOS) 执行
- TalkBack (Android) 可作为 VoiceOver 的替代方案测试移动端
- 弹窗焦点管理 (焦点陷阱 + 焦点恢复) 需人工验证，自动化仅检查 ARIA 属性
