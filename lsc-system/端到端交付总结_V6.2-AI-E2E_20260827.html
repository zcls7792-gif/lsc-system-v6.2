七、典型问题 & 经验落地（7 条）

🔗 对应经验 959665 / Failure 1 · 沙箱权限错误立刻切换不触发隔离层的执行策略

体现在 #5 修复：最初写的 spawnWithTee 依赖 bash ${PIPESTATUS[0]}，但 node:22-alpine 的 /bin/sh=ash（相当于受限 shell 沙箱）不认，直接 Bad substitution exit=2；立刻切换到 Node 原生 pipe（spawnSync stdio=pipe），在 Node 层完成"同时写终端 + logs/"的 tee 语义，本地/CI 两套 shell 环境下都一致。

# 症状 根因 修复 对应经验
1 JSDOM 报错 ICONS is not defined 直接读本地文件 file:// 时，外部共享脚本 shared/app-utils.js 未被加载 验证脚本改为通过 http://127.0.0.1:PORT URL 加载页面，确保 script src 链路生效 —
2 商家经营总览图表样式异常（stat-trend / chart-card 缺样式） merchant-admin 最初只移植了图表函数，未同步 .stat-trend / .chart-card / .chart-area 样式定义 在 merchant-admin/index.html 的 CSS 部分补齐对应类（字体、圆角、flex gap 等） —
3 test_p0_chart_logic 全部报 Assignment to constant variable const PORT = 18766; PORT++，不允许对 const 再赋值 改为 let PORT = 18766; PORT++ —
4 c8 报告 platform-admin/app.js 覆盖率 0% JSDOM 独立 vm context 中执行脚本，V8 未把执行数据关联到真实文件路径 改用 new vm.Script(src, { filename: absPath }) 显式传入源文件绝对路径，使 V8 Profile 正确落文件 959665 F1 切换隔离策略
5 模拟 CI 时 /bin/sh: 1: Bad substitution exit=2 spawnWithTee 用了 bash 专有 ${PIPESTATUS[0]}；alpine ash/dash 不支持 改为 spawnSync(stdio:['ignore','pipe','pipe'])，在 Node 层捕获 stdout/stderr → 同时写终端与 log 文件，完全不依赖 shell 特性 959665 F1（沙箱 shell 限制）
6 （风险防患）多 pipeline 共用 coverage/ 目录可能跨 run 混 lcov 默认 c8 每次写 coverage/，若 runner 不清缓存会与上次重叠 引入 coverage/$CI_COMMIT_SHORT_SHA/ 作为每次运行唯一目录，由 npm script 的 --reports-dir=${C8_REPORT_DIR:-coverage} 驱动 949301（同一次执行一目录）
7 （风险防患）长任务超时 / skipped 无法判断卡点 传统 CI 仅把终端 log 打 job log，出问题要通篇翻找 run-all 在 CI 模式下为每步生成独立 logs/step-XX-*.log，开头写 CI 构建上下文、结尾写 finished status；artifacts 设 when: always 强制上传 949301（以日志为准收敛）

九、后续建议（P1/P2 优先级）

🔗 对应经验 959665 / Failure 3 · 能力缺失的测试要明确策略 A/B

P1 · 覆盖率增强

  1. 在 .gitlab-ci.yml after_script 中加入 lcov → cobertura.xml 转换，开启 GitLab diff 逐行覆盖率（需 16.0+）
