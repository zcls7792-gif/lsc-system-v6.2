## 1. 文档概述

### 1.1 目的

本文档描述 LSC 平台 **灰度发布审批工作流**（Phase M）的详细设计，作为研发、测试、运维落地实施的技术依据。文档覆盖：

- 系统总体架构与模块边界
- 审批状态机与节点模型
- 数据库实体、索引策略与 DDL
- REST API 与 Feign 网关接口契约
- 并发控制与分布式锁设计
- 安全、可靠性、可观测性等非功能性需求
- 典型场景的完整时序示例

### 1.2 范围

本设计适用于 `lsc-release-service` 中的灰度审批子模块，与其紧密耦合的上游 `lsc-gateway` 灰度策略执行引擎（Phase I/N/P）。

**审批动作覆盖**：

| 动作（flowType） | 说明                                   | 触发网关接口                 |
| ---------------- | -------------------------------------- | ---------------------------- |
| GRADUATE         | 灰度策略"毕业"，全量切到 canary        | `POST /policies/{id}/graduate` |
| WEIGHT_CHANGE    | 灰度放量，调整 canary 权重（0~100）    | `PUT  /policies/{id}/weight` |
| ROLLBACK         | 灰度回滚，切回 baseline                | `POST /policies/{id}/rollback` |
| LAUNCH           | 首次创建并灰度（暂不通过审批单，走 upsert API）| —（预留）|

### 1.3 读者对象

- 后端研发：`lsc-release-service` / `lsc-gateway` 模块维护者
- 前端研发：管理台 `release` 菜单对接
- 测试：功能/集成测试设计
- 运维：部署、监控告警、值班手册参考

### 2.2 模块划分与职责

| 模块                          | 所在服务          | 核心职责                                                                 |
| ----------------------------- | ----------------- | ------------------------------------------------------------------------ |
| GrayApprovalController        | lsc-release       | REST API 暴露、参数校验、鉴权切面（由全局 Filter/Interceptor 完成）       |
| GrayApprovalService(Impl)     | lsc-release       | 状态机流转、审批节点匹配、并发锁、审计写入、网关接口编排                  |
| GrayApprovalFlowMapper        | lsc-release       | 审批主表 CRUD + 条件分页查询                                             |
| GrayApprovalNodeMapper        | lsc-release       | 审批节点增改查（按 flowId 聚合）                                         |
| GrayApprovalAuditMapper       | lsc-release       | 审计流水 append-only 写入                                                |
| GrayGatewayClient (Feign)     | lsc-release       | 调用 lsc-gateway 灰度执行接口；支持 Sentinel fallbackFactory（可选）      |
| GrayAuditJobHandler (XXL-JOB) | lsc-release       | 轮询网关 rollout 状态：stale tick / SLO 连续失败 / 僵尸策略 告警           |
| GrayPolicyStore               | lsc-gateway       | 灰度策略持久化 + 内存态缓存；提供 graduate/weight/rollback/stats 接口     |
| GrayRolloutCoordinator        | lsc-gateway       | 自动步进权重（Phase N）、SLO 门禁触发回滚；被审批流作为"执行后端"调用      |

### 2.3 数据流向

```
 Admin 操作 → Controller → Service(create) → DB(flow+node+audit)
                                     ↓
                         Service(approve 1..N) → DB(node, flow.approvedCount)
                                     ↓
                     approvedCount >= requiredApprovals
                                     ↓
                        flow.status = APPROVED → EXECUTING
                                     ↓
                         GrayGatewayClient.xxx(policyId) → lsc-gateway
                                     ↓
                           success → SUCCEEDED / failed → EXECUTE_FAILED
                                     ↓
                               写入 audit / executeResponse
```

## 3. 状态机设计

### 3.1 主流程状态（GrayApprovalFlow.Status）

```
        ┌──────────┐  submit  ┌──────────────────┐
        │  DRAFT   │─────────▶│ PENDING_APPROVAL │
        └──────────┘          └───────┬──────────┘
             │                         │  approve 1/2
             │ cancel                  ▼
             │                ┌──────────────────┐
             │                │  still PENDING   │──▶ (await next approver)
             │                └────────┬─────────┘
             │                         │  approve 2/2
             │                         ▼
             │                ┌──────────────────┐
             │                │     APPROVED     │
             │                └───────┬──────────┘
             │                        │ auto-execute (sync in tx)
             │                        ▼
             │                ┌──────────────────┐
             │                │    EXECUTING     │
             │                └───────┬──────────┘
             │              success  / \  gateway error
             │          ┌────────────┘ └───────────────┐
             │          ▼                              ▼
             │  ┌──────────────┐              ┌──────────────────┐
             │  │  SUCCEEDED   │              │ EXECUTE_FAILED   │
             │  └──────────────┘              └───────┬──────────┘
             │                                        │ retryExecute
             │                                        └───────▶ EXECUTING
             │
             └──── cancel (applicant)  ┌──────────────────┐
                                       │    CANCELLED     │
                                       └──────────────────┘

          Any PENDING node reject → ┌──────────────────┐
                                     │    REJECTED      │ (flow 终止)
                                     └──────────────────┘
```

### 3.2 节点状态（GrayApprovalNode.NodeStatus）

| 状态       | 进入时机                                             | 离开条件                       |
| ---------- | ---------------------------------------------------- | ------------------------------ |
| WAITING    | 审批单创建时，所有节点初始化为 WAITING               | 审批人 approve / reject        |
| APPROVED   | 审批人点击"通过"，签名 + comment                     | 终态                          |
| REJECTED   | 审批人点击"拒绝"；**整单立即 REJECTED**              | 终态                          |
| SKIPPED    | 预留：若某审批人无法履职，管理员跳过（暂未暴露 API） | 终态                          |

### 3.3 状态迁移合法性矩阵（强制校验）

Service 层在每个动作前检查，不合法抛出 `IllegalStateException`：

| 当前状态          | create | submit | approve | reject | cancel | retryExecute | auto-execute |
| ----------------- | :----: | :----: | :-----: | :----: | :----: | :----------: | :----------: |
| DRAFT             |   ✅   |   ✅   |    ❌   |   ❌   |   ✅   |      ❌      |      ❌      |
| PENDING_APPROVAL  |   ❌   |   ❌   |    ✅   |   ✅   |   ✅   |      ❌      |      ❌      |
| APPROVED          |   ❌   |   ❌   |    ❌   |   ❌   |   ❌   |      ✅      |      ✅      |
| REJECTED          |   ❌   |   ❌   |    ❌   |   ❌   |   ❌   |      ❌      |      ❌      |
| CANCELLED         |   ❌   |   ❌   |    ❌   |   ❌   |   ❌   |      ❌      |      ❌      |
| EXECUTING         |   ❌   |   ❌   |    ❌   |   ❌   |   ❌   |      ❌      |      ❌      |
| SUCCEEDED         |   ❌   |   ❌   |    ❌   |   ❌   |   ❌   |      ❌      |      ❌      |
| EXECUTE_FAILED    |   ❌   |   ❌   |    ❌   |   ❌   |   ❌   |      ✅      |      ❌      |

### 4.2 完整 DDL

见 [V6.2.0__gray_approval_flow.sql](../src/main/resources/db/migration/V6.2.0__gray_approval_flow.sql)，核心字段：

#### gray_approval_flow 索引策略

| 索引名                   | 字段                    | 用途                                           |
| ------------------------ | ----------------------- | ---------------------------------------------- |
| PRIMARY KEY              | id                      | 主键                                           |
| uk_flow_no               | flow_no                 | 业务编号唯一，供外部系统引用                   |
| idx_policy_status        | policy_id, status       | "某策略未完成审批"去重检查；防并发创建         |
| idx_applicant            | applicant               | "我发起的"列表                                 |
| idx_status_created       | status, created_at      | 待办 / 状态筛选 + 时间排序                     |

#### gray_approval_node 索引策略

| 索引名                 | 字段                   | 用途                                    |
| ---------------------- | ---------------------- | --------------------------------------- |
| PRIMARY KEY            | id                     | 主键                                    |
| idx_flow               | flow_id, node_order    | 按 flow 聚合并按顺序取节点              |
| idx_approver_status    | approver, node_status  | "我待办的"审批节点                      |

#### gray_approval_audit 索引策略

| 索引名                 | 字段                   | 用途                                   |
| ---------------------- | ---------------------- | -------------------------------------- |
| PRIMARY KEY            | id                     | 主键（append-only 单调递增）           |
| idx_flow               | flow_id, id            | 某审批单的完整审计时间线               |
| idx_action_time        | action, created_at     | 合规抽查：近 30 天所有 FLOW_SUCCEEDED |
| idx_flow_no            | flow_no                | 通过业务编号反查审计                   |

### 4.3 字段设计决策记录（ADR）

**ADR-1**：`payload_json` 使用 MySQL JSON 类型（而非 2~3 个独立字段）
- Rationale：不同 flowType 参数结构不同（WEIGHT_CHANGE 要 targetWeight；ROLLBACK 要 reason；GRADUATE 空）
- Trade-off：查询需 `JSON_EXTRACT`，但本字段仅在"执行 + 审计"时读取，不参与过滤索引

**ADR-2**：`execute_response` 使用 MEDIUMTEXT（而非 JSON）
- Rationale：网关返回字段不定，且可能含 stacktrace 长字符串；MEDIUMTEXT 无大小顾虑
- Trade-off：全文检索不如 JSON，但仅用于运维排障详情页展示

**ADR-3**：`approvedCount` 冗余列而非每次 count
- Rationale："是否达到 requiredApprovals" 是高频判断；冗余字段省去每次 join 节点表
- Trade-off：Service 层 update approvedCount 后必须再 count 一次 DB 真实值再比较（见 `approveOrReject` L152），避免并发写丢

## 5. 接口规范

### 5.1 对外 REST API（GrayApprovalController）

Base Path：`/api/release/gray`

| # | Method | Path                                   | 鉴权角色 (建议)       | 功能                  | 幂等 |
| - | ------ | -------------------------------------- | --------------------- | --------------------- | :--: |
| 1 | POST   | `/approvals`                           | 申请人 / ROLE_USER    | 创建并提交审批单      |  ❌  |
| 2 | PUT    | `/approvals/action/approve`            | ROLE_RELEASE_ADMIN    | 审批通过 / 拒绝       |  ✅* |
| 3 | PUT    | `/approvals/action/cancel`             | 申请人本人 / ADMIN    | 撤销（仅 DRAFT/PENDING）|  ✅ |
| 4 | PUT    | `/approvals/action/retry-execute`      | ROLE_RELEASE_ADMIN    | 重试网关执行          |  ✅ |
| 5 | GET    | `/approvals`                           | ROLE_RELEASE_VIEWER   | 分页查询列表          |  ✅ |
| 6 | GET    | `/approvals/{flowId}`                  | ROLE_RELEASE_VIEWER   | 详情（flow+nodes+audits）|✅ |
| 7 | PUT    | `/approvals/{flowId}/force-status`     | ROLE_SUPER_ADMIN 测试 | 强制改状态（生产禁用）|  ❌  |

> *API-2 同一审批人对同一节点重复审批 → 服务端检测该人已在已审批节点，或无 WAITING 节点 → 抛错，但不会造成脏写（结合分布式锁可视为实际上幂等）。

#### 5.1.1 创建审批单 `POST /api/release/gray/approvals`

**Request Body**：
```json
{
  "flowType": "GRADUATE",
  "policyId": "order-service-v2.1-20260903",
  "applicant": "alice@lianshengtong.com",
  "title": "订单服务v2.1灰度毕业",
  "applyReason": "观察期7天错误率低于0.1%，SLA达标",
  "requiredApprovals": 2,
  "approvers": ["bob@lianshengtong.com", "carol@lianshengtong.com"],
  "payload": null
}
```

| 字段              | 类型   | 必填 | 说明                                                                 |
| ----------------- | ------ | ---- | -------------------------------------------------------------------- |
| flowType          | enum   | ✅   | GRADUATE / WEIGHT_CHANGE / ROLLBACK / LAUNCH                         |
| policyId          | string | ✅   | lsc-gateway 中 `gray_policy.policy_id`                               |
| applicant         | string | ✅   | 申请人（=当前登录用户名，后端再次校验）                               |
| title             | string | ❌   | 默认 `{flowType}/{policyId}`                                          |
| applyReason       | string | ❌   | 申请原因                                                             |
| requiredApprovals | int    | ❌   | 默认 2；范围 [1..5]，超出自动 clip                                   |
| approvers         | list   | ❌   | 指定审批人；为空则从 ROLE_RELEASE_ADMIN 池中匹配（先到先签）          |
| payload           | object | ❌   | WEIGHT_CHANGE: `{"targetWeight":50}`; ROLLBACK: `{"reason":"xxx"}`  |

**Success Response 200**：
```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "id": 1001,
    "flowNo": "GA20260903123456",
    "flowType": "GRADUATE",
    "policyId": "order-service-v2.1-20260903",
    "status": "PENDING_APPROVAL",
    "requiredApprovals": 2,
    "approvedCount": 0,
    "createdAt": "2026-09-03 10:22:00"
  }
}
```

#### 5.1.2 审批 `PUT /api/release/gray/approvals/action/approve`

```json
{
  "flowId": 1001,
  "approver": "bob@lianshengtong.com",
  "approved": true,
  "comment": "错误率0.07%<0.1%，同意毕业",
  "signature": "BASE64(HASH(password+timestamp)) // 可选合规要求"
}
```

**失败场景响应**：
```json
{ "code": 409, "message": "flow not pending: EXECUTE_FAILED" }
{ "code": 409, "message": "no waiting node" }
{ "code": 503, "message": "cannot acquire distributed lock for flow 1001" }
```

#### 5.1.3 撤销 / 重试

Cancel（仅 DRAFT/PENDING）：
```json
{ "flowId": 1001, "operator": "alice@lianshengtong.com", "reason": "发现新bug，暂停上线" }
```

RetryExecute（仅 EXECUTE_FAILED / APPROVED 未执行）：
```json
{ "flowId": 1001, "operator": "bob@lianshengtong.com" }
```

#### 5.1.4 详情

`GET /api/release/gray/approvals/1001` 返回 `GrayApprovalDTO.Detail`：
```json
{
  "flow": { ...GrayApprovalFlow... },
  "nodes": [
    { "nodeOrder":1, "approver":"bob@...", "nodeStatus":"APPROVED",
      "comment":"同意", "decidedAt":"2026-09-03 10:25:00" },
    { "nodeOrder":2, "approver":null, "nodeStatus":"WAITING" }
  ],
  "audits": [
    { "action":"FLOW_CREATED", "operator":"alice@...",
      "detailJson": { "flowType":"GRADUATE", ... }, "createdAt":"..." },
    { "action":"NODE_APPROVED", ... }
  ]
}
```

### 5.2 Feign 跨服务接口（GrayGatewayClient → lsc-gateway）

`@FeignClient(name="lsc-gateway", path="/api/gateway/gray")`

| 方法           | HTTP                                 | 入参                                            | 成功返回                                |
| -------------- | ------------------------------------ | ----------------------------------------------- | --------------------------------------- |
| graduate       | POST `/policies/{id}/graduate`       | policyId, operator header, reasonBody(含flowNo) | `{graduated:true, promotedWeight:100}`  |
| changeWeight   | PUT  `/policies/{id}/weight`         | policyId, operator header, weightPercent        | `{oldWeight:10, newWeight:50}`          |
| rollback       | POST `/policies/{id}/rollback`       | policyId, operator header, reason(query)        | `{rolledBack:true, baselineWeight:100}` |
| policyStats    | GET  `/policies/{id}/stats`          | policyId                                        | errorRate / qps / p99 等 SLO 指标       |
| rolloutStatus  | GET  `/rollout/status`               | —                                               | coordinator健康度 + 全部策略概览        |
| rolloutDetail  | GET  `/policies/{id}/rollout`        | policyId                                        | 自动步进状态 / SLO 门禁配置             |
| rolloutAdvanceStep | POST `/policies/{id}/rollout/advance-step` | policyId, operator header, reason        | `{advancedFromStep:i, toStep:j}`        |

**失败降级**：
- Sentinel 可选：`fallbackFactory = GrayGatewayClientFallbackFactory.class`
- 当前 Service 已用 try/catch 捕获任何 Exception → 写 `EXECUTE_FAILED` + 完整错误到 executeResponse

## 6. 核心流程与并发控制

### 6.1 创建审批单时序

```

     │                    │                  │                  │              │
     │─ POST /approvals ─▶│                  │                  │              │

     │                    │                  │─ generateFlowNo  │              │
     │                    │                  │─ insert flow DRAFT             │
     │                    │                  │─────────────────▶│              │
     │                    │                  │  (id=1001)       │              │
     │                    │                  │─ insert N nodes WAITING         │
     │                    │                  │─────────────────▶│              │
     │                    │                  │─ audit FLOW_CREATED            │
     │                    │                  │───────────────────────────────▶│
     │                    │                  │─ flow.status=PENDING           │
     │                    │                  │─ updateById                    │
     │                    │                  │─────────────────▶│              │
     │                    │                  │─ audit FLOW_SUBMITTED          │
     │                    │                  │───────────────────────────────▶│
     │   200 + flow       │◀─────────────────│                  │              │
     │◀───────────────────│                  │                  │              │
```

### 6.2 审批并发控制（分布式锁）

**问题**：两个管理员同时对同一审批单点击"通过"，可能导致：
1. 重复写同一个 WAITING 节点（先到先得竞争）
2. approvedCount 超卖（2 次审批都认为自己是第 2 次，各 +1 → 计数翻倍或错误）

**方案**：两级锁 + DB 真实 count 复核：

```
approveOrReject(flowId=1001):
  1. AcquiredLock lock = tryLock(flowId)
     ├─ Redisson fairLock("gray:approval:flow:1001") tryLock(10s wait, 60s lease)
     └─ 降级：JVM ConcurrentHashMap<flowId, ReentrantLock> tryLock()
  2. select flow → 校验 status == PENDING_APPROVAL
  3. 取 WAITING 节点（优先匹配 approver，否则第一个 WAITING）
  4. 更新 node.status = APPROVED/REJECTED
  5. 若 REJECT → flow.status=REJECTED；return
  6. 【关键】approved = SELECT COUNT(*) FROM node WHERE flowId=1001 AND APPROVED
     → （不用内存里 +1，直接读库真实值）
  7. flow.approvedCount = approved
  8. approved >= required ? APPROVED → executeApprovedFlow : NODE_APPROVED 审计
  9. lock.close() (try-with-resources 自动)
```

**死锁风险**：每 flowId 独立锁，无交叉依赖 → 不会死锁。
**锁超时**：60s 足够（网关 HTTP 默认 30s），超时后 Redisson watchdog 续约（默认开启）。

### 6.3 审批通过自动执行网关编排（executeApprovedFlow）

```
 [APPROVED]
     │
     ▼
 flow.status = EXECUTING + audit FLOW_EXECUTING
     │
     ├─ switch flowType:
     │   GRADUATE       → gatewayClient.graduate(policyId, operator, {approvalFlowNo})
     │   WEIGHT_CHANGE  → payload.targetWeight → gatewayClient.changeWeight(...)
     │   ROLLBACK       → payload.reason      → gatewayClient.rollback(...)
     │   LAUNCH         → UnsupportedOperationException
     │
     ▼
 成功?────Yes────▶ flow.status=SUCCEEDED + 写 executeResponse + FLOW_SUCCEEDED 审计
     │
     No
     ▼
 flow.status=EXECUTE_FAILED + 完整错误(含exception stack)写 executeResponse
            + FLOW_EXECUTE_FAILED 审计 (costMs, success=false)
            + 暴露 retryExecute API 给运维手动重试
```

> **设计取舍**：默认同步执行网关（非异步消息）。理由：审批本身频率极低（<50 次/天），同步能把失败立刻暴露给最后一个审批人。异步方案（发 MQ → 消费端执行）能缓解锁持有时长，但增加了消息持久化/消费幂等复杂度。后续 QPS 上涨时可改造。

## 7. 审计与合规

### 7.1 审计动作全集（GrayApprovalAudit.action）

| Action                 | 触发时机                                             | detailJson 示例内容                     |
| ---------------------- | ---------------------------------------------------- | --------------------------------------- |
| FLOW_CREATED           | 审批单 insert + 还在 DRAFT（但当前默认立刻提交）     | flowType, policyId, requiredApprovals  |
| FLOW_SUBMITTED         | 状态 DRAFT → PENDING_APPROVAL                        | (空)                                    |
| NODE_APPROVED          | 某节点通过，尚未达 requiredApprovals                 | nodeOrder                               |
| FLOW_APPROVED          | 达到 requiredApprovals，整单通过                     | approvedTotal                           |
| FLOW_REJECTED          | 任一节点拒绝 → 整单 REJECTED                         | comment                                 |
| FLOW_CANCELLED         | 申请人撤销                                           | reason                                  |
| FLOW_EXECUTING         | 状态 APPROVED → EXECUTING                            | (空)                                    |
| FLOW_SUCCEEDED         | 网关接口成功                                         | costMs, success:true                    |
| FLOW_EXECUTE_FAILED    | 网关接口失败/抛异常                                   | costMs, success:false, exception, msg  |
| FLOW_FORCE_STATUS_*    | 测试接口强制改状态                                   | (空) / 生产禁止                         |

### 7.2 审计流水完整性约束

1. **append-only**：Mapper 只暴露 `insert` + `selectList`，没有 update/delete 方法。
2. **事务一致性**：所有 audit 写入与对应 flow/node 更新处于同一 `@Transactional` 内，要么都写要么都不写。
3. **链上存证（可选）**：`chain_tx_hash` 字段预留。接入区块链/不可变日志系统后，XXL-JOB 批量取未存证 audit 写链并回填 hash。

## 10. 可靠性与失败处理

### 10.1 失败矩阵

| 失败点                     | 状态迁移               | 恢复手段                                          |
| -------------------------- | ---------------------- | ------------------------------------------------- |
| 创建审批单 DB 写失败       | — (未入库)             | 前端重试（幂等需先 query by flowNo 去重）         |
| 审批接口拿不到锁          | 不改变（HTTP 503）     | 前端提示"其他审批人正在操作，请 10s 后重试"        |
| 网关调用超时/5xx          | EXECUTE_FAILED         | `retryExecute` 手动重试；或后续自动重试定时任务    |
| 网关调用成功但写回 DB 失败| DB 回滚 → EXECUTING    | XXL-JOB 扫描 EXECUTING > 2min → 读 gateway policyStats 判定真实状态并修正 |
| XXL-JOB 调度不可达        | —                      | 告警：XXL-JOB admin 自带 executor 失联告警         |

### 10.2 推荐追加的"自愈"定时任务

```
Job: grayApprovalSelfHeal (每 5 分钟)
  1) 扫 status=EXECUTING 且 updated_at < now-2min
     → 调 gatewayClient.policyStats(policyId)
       → policy.status=GRADUATED/ROLLED_BACK → 本地 SUCCEEDED
       → policy.status=ACTIVE 且权重未变 → 本地 EXECUTE_FAILED
  2) 扫 EXECUTE_FAILED 且 retry_count < 3 且 last_retry > 10min
     → 自动 retryExecute（operator=system:selfheal，审计写入）
```

### 10.3 网络/服务可靠性

- Feign OkHttp 连接池：`feign.okhttp.enabled=true`，`readTimeout=30s`
- Sentinel 熔断：`lsc-gateway` 连续 5 次 5xx → 熔断 30s，fallback 返回失败原因
- Nacos 健康检查：release-service 自动感知 gateway 实例上下线
