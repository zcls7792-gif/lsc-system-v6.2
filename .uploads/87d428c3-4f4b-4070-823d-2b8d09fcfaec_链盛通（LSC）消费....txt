版本变更说明
V7.7.1 在 V7.7.0 基础上修订，完整继承其业务定位、双轨架构与合规框架，不改变 LSC 消费回馈权益的基本性质。本版针对 V7.7.0 评审发现的 11 项硬伤逐条修复，所有修复均为可开发、可落库、可测试口径。
第一，释放规则参数化。释放速率区间维持 0.05% 至 0.10% 硬编码；周转率默认区间调整为 1.0% 至 2.0%，可由超级管理员发起、另一名超级管理员双签审批后在硬性边界 0.5% 至 2.5% 内调节。速率插值公式引用当前生效的 w_min 与 w_max 参数，默认配置下插值分母为 1.0%。
第二，推荐奖励全面改造。废止原"被推荐人首单人民币实付金额 10% 从推荐人锁定池加速释放"机制，改为独立商城优惠券，按成功推荐人数实行四档阶梯奖励（第 1 人 20 元券满 200 元 30 天，第 2 人 30 元券满 250 元 40 天，第 3 人 40 元券满 300 元 50 天，第 4 人及以后 40 元券满 300 元 60 天）；新增券模板、用户券、券流水三类数据模型与独立优惠券服务；优惠券与 LSC 在同一订单中互斥、不可同时使用；券抵扣部分不产生 LSC。
第三，账本批次化与最小单位制落地。采用 Grant Lot 权益批次表、Available Lot 可用批次表为事实明细，账户表仅为聚合快照；全库权益数量统一以最小单位 LSC-unit 整数存储，1 LSC 等于 10000 LSC-unit；删除 Grant Lot 中已无业务含义的 accelerated_amount 字段。
第四，退款可撤销赠送债务闭环落库。订单明细表新增 clawback_required、clawback_completed、clawback_pending 三个状态字段与 recovery_pending_amount 待追偿金额字段，新增权益追偿记录表；扣回顺序为对应 Grant Lot 未释放余额、Available Lot 可用余额、冻结余额，不足部分挂待追偿，其后新增可用权益优先冲抵。
第五，版本口径统一。全文版本号统一为 V7.7.1，不再出现"V7.7.0引入"等正文与封面不一致的表述。
第六，单位口径全库统一。商品、订单、配置、流水、报表中所有权益数量字段统一为 unit 整数口径，对外展示层除以 10000 显示为 LSC。
第七，优先级修正。Available Lot 有效期管理与 FEFO 最早过期先用，由原 P1 提升为 P0，与 365 天到期作废的合规要求同级交付。
第八，账本描述与表结构一致。账户表不挂批次字段；批次是独立事实表，账户表仅保存三个聚合余额与版本号。
第九，术语净化。对外文案与对外接口禁止出现进货价、进销差、利润率等词汇；内部研发文档中该系数统一命名为 grant_coefficient（经营空间回馈系数，默认 0.80，可双签调节），并显式标注"内部口径、禁止外泄"。
第十，财务与 AI 两条软约束硬化。财务确认要求上线前取得注册会计师书面账务处理意见并据此冻结配置；AI 自动化决策给出必须人工复核的事项清单、48 小时复核时限与 5 个工作日申诉答复时限。
第十一，合作方主体显式化。新增 1.2 节对外部合作方的处理条款；"宏博"在本系统中的法律角色以另行签署的书面合作协议为准，系统不为任何外部合作方开设 LSC 账户或权益通道（详见 1.2 第六款）。
术语规范：对外与前端展示统一使用消费回馈、赠送、抵扣、优惠、自营兑换；内部核算口径统一使用平台商品经营空间；前端展示、对外宣传、短视频物料禁止展示任何内部核算公式。
第一章 系统总体设计
1.1 系统定位
链盛通是自营供应链双轨消费平台，同时服务两类用户群体。B 端为持证经营商户，采购商品用于二次销售经营；C 端为终端个人消费者，采购商品用于自用。
平台作为供应链经营主体，向上游合规供应商采购实体商品，依托链盛通权益商城面向 B 端商户、C 端消费者开展实物商品销售，基于真实、可溯源的人民币订单，向符合条件的用户发放 LSC 链盛通消费回馈权益。
LSC 定义：平台消费回馈权益，仅可在平台自营商城用于商品抵扣、商品兑换。LSC 不属于资产、不属于投资标的、不构成兑付凭证，无现金兑付承诺、无增值属性。LSC 仅限链盛通自营体系内使用，不可转让、不可提现、不可兑现、不可跨账户流转，到期自动失效；全部限制在代码层、接口层强制锁定，不存在任何权益到人民币的通道。
1.2 法律主体结构
第一款，平台主体：中创链盛科技有限公司，负责权益系统技术运营与平台管理，为独立法人，独立核算、独立纳税。
第二款，供应链运营主体：链盛通供应链有限公司，负责商品采购、库存管理、仓储发货、B/C 两端商品履约与售后，为独立法人，独立核算、独立纳税。
第三款，B 端商户属于外部独立经营主体，自主负责二次销售与门店运营，与平台之间是商品购销合作关系，不是平台代理、分销层级或权益层级。
第四款，上游供应商仅与供应链公司签订购销合同，对公人民币结算，完成四单匹配与合规开票，与 LSC 权益体系无任何权责关联；供应商不接收、不持有、不兑换 LSC。
第五款，终端用户分为 B 端认证商户与 C 端个人消费者两类。
第六款，外部合作方条款（适用宏博及其他业务合作方）：任何外部合作方与平台之间的权利义务、收益结算、品牌使用、渠道分工，均以另行签署的书面合作协议为准。系统层面执行三条硬规则：其一，不为外部合作方开设 LSC 账户、权益批次账户或优惠券资金账户；其二，不存在以 LSC、优惠券或消费数据向合作方兑付、分成、清分的接口；其三，合作方若参与供货，按第四款供应商管理，仅人民币对公结算；若参与获客，其奖励只能以人民币服务费或独立优惠券形式按合同结算，不与用户 LSC 锁定池挂钩。宏博在本系统中的具体角色（供应链合作方、渠道合作方或其他）在合作协议签署前标记为待确认事项，未确认前系统按"外部业务合作方、不进入权益与资金清分"处理。
1.3 商业模式
平台自营采购、自建库存、自营履约，支持两类真实实物交易场景。
C 端零售业务：个人消费者按零售价采购自用商品，订单履约完成后，按零售对应的平台商品经营空间与回馈系数核算消费回馈权益。
B 端商户采购业务：持证商户完成资质审核后解锁商户采购价，采购货品用于二次经营销售，订单履约完成后，按商户采购对应的平台商品经营空间与回馈系数核算消费回馈权益。
内部核算演示（仅内部研发与经营分析使用，禁止外泄）：商品采购成本 80 元，B 端采购价 100 元，C 端零售价 130 元；经营空间回馈系数 grant_coefficient 默认 0.80；B 端全额人民币订单赠送 16 LSC（160000 unit），C 端全额人民币订单赠送 40 LSC（400000 unit）。负经营空间商品赠送为 0，系统不允许负赠送。
1.4 盈利模式
收入来源三项。第一，C 端商品零售经营收益，即零售价对应的经营空间扣除仓储、物流、履约成本。第二，B 端商品采购经营收益，即采购价对应的经营空间扣除履约成本。第三，供应链增值服务费，面向合规供应商提供质检、对账、账期管理、溯源等合法服务收取费用。
成本来源三项。第一，采购与履约成本，含采购、仓储、物流、售后。第二，平台运营成本，含研发、运维、客服、服务器、合规备案。第三，营销成本，含 LSC 实际核销部分与优惠券实际核销部分；其具体会计确认时点与科目，以注册会计师书面账务处理意见为准（详见 9.3）。
1.5 系统环境适配标准与务实性能目标
服务端最低适配 Java 17，数据库最低适配 MySQL 8.0.28，缓存最低适配 Redis 7.0.0。用户端最低适配微信小程序基础库 2.10.0、iOS 12.0、Android 8.0。管理端与供应商端最低适配 Chrome 90、Edge 90、Safari 14。
性能目标务实起步：一期不设 10 万 QPS 目标，按单库逻辑分表或 4 至 8 个物理分片部署，核心账务接口 P99 不超过 500 毫秒；压测基线为单分片 1000 QPS 账务写、全站 3000 QPS 混合读。预留水平拆分路径，当账务写连续 30 天超过单分片水位 70% 时，按 32 分片方案扩容（8 物理库乘 4 逻辑表，user_id 取模 32），跨分片事务采用 Seata AT。所有容量决策以监控数据为准，不提前过度建设。
1.6 AI 能力分层架构
系统保留 AI 能力模块，每个 AI Agent 设独立启用开关，默认全部为 false；开关仅超级管理员可切换，切换需填写原因并记录审计日志。关闭的 Agent 不运行、不占资源、不产生费用，对应流程走人工或固定规则路径。
运营 AI 包含商品审核 Agent、AI 客服 Agent、管理员智能助手 Agent、防套利风控 Agent、商户资质 AI 初审 Agent、B 端窜货风险识别 Agent。各 Agent 经消息队列异步通信，独立部署、独立升级、故障自动熔断，不影响核心交易。
决策 AI 包含销量预测、库存补货建议、定价辅助、智能对账，输出仅供管理员参考，不允许直接修改任何核心业务参数。
AI 人工复核与申诉硬规则（符合个人信息保护法第 24 条）：下列重大决定 AI 只能给建议，必须人工复核确认后才生效——其一，冻结用户账户或权益；其二，取消 B 端商户资格；其三，对已完成订单拒绝或扣回权益；其四，认定窜货并处罚；其五，认定虚假商户或刷单套利。人工复核时限为 AI 标记后 48 小时内完成；用户申诉通道在处理结果通知中明示，平台在收到申诉后 5 个工作日内答复，复核与申诉全程留痕。
每个 AI Agent 启用前，按《生成式人工智能服务管理暂行办法》完成算法备案、安全评估或登记；未完成备案不得开启。
1.7 合规十二条硬底线
第一条，LSC 全链路闭环，转让、提现、兑现、跨账户流转接口全部拦截，无任何权益到人民币通道。
第二条，权益发放基数为平台商品经营空间，回馈系数与发放上限受代码与双签审批约束，绝对安全上限 100% 硬编码。
第三条，全平台隐藏采购成本与内部经营空间；B 端仅可见采购价，C 端仅可见零售价，不存在从前端数据反推内部成本的路径。
第四条，混合支付仅人民币实付部分发放权益；LSC 抵扣部分、优惠券抵扣部分均不产生新权益，代码强制校验；同一订单优惠券与 LSC 互斥，只能二选一，结算引擎在下单与支付回调两处强制校验。
第五条，单笔订单 LSC 抵扣默认上限 20%（可配置），硬性上限 50% 硬编码，后台无突破入口。
第六条，不设资金归集池、不设监管账户清分、不做价值承诺、不使用保本类宣传话术。
第七条，上游供应商只收人民币，系统无供应商权益模块，与权益体系无交互通道。
第八条，无真实人民币消费不发放权益，刷单、异常交易自动拦截且不发放。
第九条，释放速率 0.05% 至 0.10% 硬编码；周转率默认 1.0% 至 2.0%、可双签调节，硬性边界 0.5% 至 2.5% 编译锁定；二次校验越界直接终止任务并告警两名超级管理员。
第十条，权益唯一来源为真实人民币消费；推荐奖励为独立商城优惠券，与锁定池完全脱钩，不新增权益发行。
第十一条，B 端商户必须通过营业执照资质审核方可解锁采购价；禁止个人冒用资质冒充 B 端套取低价。
第十二条，B 端采购协议约定禁止跨区域窜货、禁止低价倾销；核实违规后取消 B 端权限并冻结账户权益，冻结决定适用 1.6 人工复核与申诉规则。
第二章 权益商城功能体系
2.1 商城定位
权益商城为链盛通自营商品销售与 LSC 使用的唯一核心场景，覆盖家具、家电、日用品、食品、家居等品类。商品均为真实采购、真实库存、真实履约。LSC 在自营体系内全品类通用，不绑定产生权益的商品。
C 端展示零售价与赠送权益数，个人中心展示锁定余额、可用余额、冻结余额、今日释放到账、累计释放到账，并展示当前权益规则说明（锁定、每日释放、释放率范围、周期不固定、有效期、抵扣上限）；不展示释放进度条、释放年限、预计释放完成时间。
B 端商户专区在资质审核通过后可见，展示采购价、采购赠送权益、批量下单入口、采购台账与商户订单管理。
2.2 用户身份与商品价格体系
用户身份 user_type 枚举：0 未认证用户，1 为 B 端认证商户，2 为 C 端个人消费者。未认证用户按 C 端零售价浏览；资质审核通过后标记为 1 并解锁采购价。
商品实行双价格双视图。retail_price 为 C 端零售价，全部用户可见；b_price 为 B 端采购价，仅 B 端认证账号可读，C 端请求在接口层直接过滤该字段；cost_price 为采购成本，加密存储，仅超级管理员经事由审批后解密查看。
赠送权益两套独立核算：C 端按零售价对应经营空间，B 端按采购价对应经营空间。商品表存储的赠送基准数 grant_points_unit 为全额人民币支付口径，以 unit 整数存储（C 端示例商品为 400000，B 端视图为 160000）。负经营空间商品赠送基准为 0。
新增功能：B 端资质线上审核（营业执照上传、OCR 识别、人工复核、审批留痕）；B 端采购门槛配置（最低起订量、月度最低采购频次）；窜货风控台账；违禁词双层校验（系统词库加 AI 辅助，AI 开关独立）。
商品状态：0 下架，1 上架，2 审核中，3 缺货。
2.3 混合支付与优惠券互斥规则
结算方式三选一：纯人民币支付、人民币加 LSC 混合支付、人民币加优惠券支付。优惠券与 LSC 在同一订单中互斥，不允许同时使用；用户选择优惠券时 LSC 输入框锁定不可用，选择 LSC 时优惠券不可勾选，前端限制之外结算引擎在下单创建与支付回调两个环节再次强校验，任一订单 coupon_amount 大于 0 且 lsc_amount_unit 大于 0 即拒绝并返回错误码 42206（券与权益不可同单使用）。
使用 LSC 时的校验：可用余额不少于拟使用量；LSC 抵扣额不超过订单金额乘以当前抵扣比例（默认 20%，硬顶 50%）。使用优惠券时的校验：券状态为未使用、在有效期内、订单商品适用、订单金额满足券门槛。
人民币实付金额等于订单金额减 LSC 抵扣额，或订单金额减优惠券面额，二者只居其一。
赠送权益计算：以商品为单位逐件计算后汇总，公式为该商品经营空间回馈额乘以人民币实付占比，即 grant_coefficient 乘以（销售价减采购成本）乘以（该商品分摊后人民币实付金额除以销售价），结果以 unit 为单位向下取整。LSC 抵扣部分与优惠券抵扣部分均不计入人民币实付，不产生权益。
示例（内部口径）：C 端商品售价 130 元、采购成本 80 元、回馈基准 40 LSC。全额人民币支付赠 40 LSC。使用一张 20 元优惠券（不使用 LSC）时，人民币实付 110 元，赠 40 乘 110 除 130 等于 33.84，向下取整为 33 LSC（330000 unit）。使用 LSC 抵扣 26 元（不使用券）时，人民币实付 104 元，赠 40 乘 104 除 130 等于 32.0，向下取整为 32 LSC（320000 unit）。两种抵扣不能叠加。B 端商品采购价 100 元、回馈基准 16 LSC，规则相同。
结算页在支付前清晰展示商品总额、所选抵扣方式（券或 LSC，二选一）、抵扣金额、人民币实付与预计赠送权益。
2.4 退款规则与可撤销赠送债务闭环
C 端订单适用法定七日无理由退货与质量问题三包；B 端采购订单按购销合同售后条款执行。退款按商品行明细处理。
退款财务处理：人民币部分按原支付渠道退回；优惠券按 2.4 第四款处理；LSC 已核销部分按"已用不追溯、未用退回"原则处理；对应订单已赠送的 LSC 必须按本商品行实际赠送数量启动扣回。
优惠券退款规则：订单退款时，未核销的券退回用户券账户并恢复原有效期；已核销的券不返还现金、不补发，随退款一并失效；部分退款按平台公示的售后规则处理。
可撤销赠送债务闭环：每笔订单明细记录本次赠送对应的 Grant Lot。退款触发扣回时按固定顺序执行。第一顺位，从该商品行对应 Grant Lot 的未释放余额扣回；第二顺位，从用户全部 Available Lot 可用余额按 FEFO 原则扣回；第三顺位，从冻结余额扣回。三顺位合计仍不足的，差额写入权益追偿记录（recovery_pending），不记坏账、不做豁免；用户此后新增可用权益时系统自动优先冲抵待追偿，直至清零。
订单明细表以三个状态位管理闭环：clawback_required（应扣回数量，大于 0 即需要处理）、clawback_completed（已完成扣回数量）、clawback_pending（待追偿数量）。三个数量满足应扣回等于已完成加待追偿；待追偿清零时该明细闭环关闭。所有扣回、追偿、冲抵动作写入权益流水，幂等可重放。每日终了自动校验订单、批次、账户、追偿四方账务一致性，不平账阻断次日释放任务并告警。
2.5 订单状态与订单类型
订单状态：0 待支付，1 已支付，2 已发货，3 已完成，4 已取消，5 退款中，6 已退款，7 部分退款。
订单类型：0 纯人民币 C 端订单，1 混合支付 C 端订单，2 纯人民币 B 端采购订单，3 混合支付 B 端采购订单。是否使用优惠券、是否使用 LSC 以独立字段记录，不扩展订单类型枚举；系统强制同一订单二者至多一个为正值（互斥）。
支付渠道：接入持牌支付机构收单，平台自营履约，不自建支付通道。
第三章 LSC 消费回馈权益核心规则
3.1 权益赠送规则
触发条件：订单状态为已完成、真实人民币消费、无风控异常、非刷单套利订单。
C 端按零售经营空间、B 端按采购经营空间分别核算，逐商品行计算、汇总后以 unit 向下取整入 Grant Lot。非人民币消费零赠送，无例外通道；退款、取消、异常订单拦截赠送；券与 LSC 抵扣部分永久不产生权益；推荐优惠券不属于权益发行。
赠送的权益初始全部为锁定状态，自赠送次日起按 3.2 规则逐日释放。
3.2 动态释放规则
核心参数：日释放速率区间 rate_min 等于 0.05%、rate_max 等于 0.10%，硬常量，编译后不可修改。周转率默认下限 w_min 等于 1.0%、默认上限 w_max 等于 2.0%，可双签调节；硬性边界 w_min_hard 等于 0.5%、w_max_hard 等于 2.5%，编译锁定，任何配置超出边界直接拒绝保存。
第一步，计算平台级周转率 w。w 等于前一日全平台可用 LSC 净消耗量（订单抵扣加到期作废，扣除退款退回）除以前一日末全平台可用余额。平台级 w 对全部用户一致生效，避免按用户计算导致的新用户分母为零与操纵问题。
第二步，读取当前生效的 w_min、w_max，分段计算当日速率 rate。w 小于等于 w_min 时，rate 等于 rate_min；w 大于等于 w_max 时，rate 等于 rate_max；w 位于区间内时，rate 等于 rate_min 加（rate_max 减 rate_min）乘以（w 减 w_min）除以（w_max 减 w_min），线性插值。当 w_max 等于 w_min 的异常配置出现时，任务拒绝执行并告警。
第三步，逐用户、逐 Grant Lot 计算当日释放量。T_release 等于该 Lot 剩余锁定余额对应日释放量，以 unit 向下取整，转入该 Lot 对应的新 Available Lot；累计释放不超过该 Lot 原始数量。
数学验证（以初始锁定数量为基数的定额线性口径）：rate 等于 0.05% 时 2000 天约 5.48 年释放完毕；0.10% 时 1000 天约 2.74 年；0.075% 时约 1333 天即 3.65 年。实际周期随每日速率浮动，约 2.74 至 5.48 年，不固定、不构成承诺。
w_min、w_max 修改流程：超级管理员发起，另一名超级管理员审批，双签通过后生效；记录操作人、审批人、修改前后值、原因与时间，写入比例调整审计表永久留存。
硬约束与容错：每日释放计算完成后对 rate 与配置边界二次校验，越界直接终止任务、推送告警给两名超级管理员；分批执行每批 10 万条，支持健康检查、断点续跑、全量补偿与账务比对阻断；无 180 天封顶；释放直至每个 Grant Lot 清零。
3.3 使用规则
1 unit 为最小记账单位；10000 unit 抵扣 1 元人民币货款，即 1 LSC 抵扣 1 元。LSC 在自营全品类通用，不绑定商品品类，不区分 B/C 来源批次。
单笔抵扣默认上限订单金额 20%（可配置），硬性上限 50% 硬编码。使用时按 FEFO（最早过期先用）原则选择 Available Lot 扣减，逐 Lot 记录剩余。
转让、兑现、提现、跨账户流转在接口层全部拒绝；使用场景仅限链盛通自营商城与供应链公司自营销售。
3.4 有效期与作废
锁定状态不计有效期；权益自释放进入 Available Lot 之日起 365 天内有效，到期自动作废，作废不可恢复、不补偿。每日定时任务扫描到期批次批量作废并写流水；到期前 30 天、7 天推送提醒。规则在注册协议中明示。
3.5 权益账本四层模型
账本分四层：Grant Lot（赠送批次，锁定事实）、Locked（锁定聚合）、Available Lot（可用批次，有效期事实）、Consume 或 Expire（核销或过期事件）。流水表 Ledger 为唯一事实源，账户表 Account 为聚合快照；任何余额以批次与流水重算结果为准，账户余额可重建。
账户表仅保存 user_id、total_locked、total_available、total_frozen、version、updated_at；批次关系通过独立批次表的 user_id 与 source_grant_lot 关联，不在账户表挂批次字段。
全部赠送入锁定、每日释放、核销、退回、作废、扣回、追偿冲抵、风控冻结解冻均写流水，含前后余额、幂等键、订单号；余额更新采用乐观锁加幂等键；每日日终对账，流水合计与批次合计、账户快照核对，异常告警阻断。
3.6 最小单位制
全系统权益数量采用最小单位制：1 LSC 等于 10000 LSC-unit。数据库、接口、配置、定时任务、对账全部保存与传输 unit 整数，禁止使用浮点类型保存权益数量；展示层按 10000 换算，消费者端显示两位小数 LSC（如 16.00），后台可显示四位至六位精度。示例：16 LSC 等于 160000 unit；某 Lot 当日释放 160000 乘 0.0005 等于 80 unit 即 0.008 LSC，每日精确累计，不产生尾差。
3.7 推荐奖励独立优惠券
推荐关系仅一级直推，注册时绑定、不可修改。被推荐人完成首单真实人民币消费（订单已完成，B/C 首单均可）触发一次奖励，每位被推荐人仅触发一次。
奖励内容为按成功推荐人数递增的四档固定面额商城优惠券，每位被推荐人仅就其首单触发一次：
第一档，推荐人名下第 1 位被推荐人首单完成，发 20 元优惠券，满 200 元可抵扣，有效期 30 天。 第二档，第 2 位被推荐人首单完成，发 30 元优惠券，满 250 元可抵扣，有效期 40 天。 第三档，第 3 位被推荐人首单完成，发 40 元优惠券，满 300 元可抵扣，有效期 50 天。 第四档，第 4 位及以后每位被推荐人首单完成，均发 40 元优惠券，满 300 元可抵扣，有效期 60 天。
档位按推荐人名下"已触发首单奖励的被推荐人累计人数"实时确定，人数计数只增不减；退款不回退已发券档位（券本身按 2.4 退款规则处理）。四档面额、门槛、有效期以券模板预置，调整需超级管理员双签。奖励不与首单金额挂钩、不按比例计算、不触碰推荐人 LSC 锁定池，不形成上下级权益关系。
优惠券与 LSC 的边界：优惠券是独立营销工具，有独立模板、账户、流水与过期规则；券与 LSC 在同一订单互斥、不可叠加；券核销部分不产生 LSC；券不可转让、不可兑现；推荐奖励的发放、核销、过期不写入 LSC 流水表（流水表 type 6 保留为"已废弃，原推荐加速释放"，不再产生新记录）。
3.8 防套利规则
保留高频小额刷单检测、自买自返识别（地址、支付账户、设备指纹、IP 关联）、团购代付异常检测；命中高风险自动停止赠送并冻结账户，冻结决定按 1.6 规则人工复核。B 端叠加资质核验、窜货监测、虚假商户识别与采购门槛管控（详见第六章）。
第四章 供应链体系
4.1 采购管理
供应商准入含营业执照与资质审核、合同签署、对公账户校验。采购流程为选品、询价、采购订单、质检入库、对账结算。采购订单状态：0 草稿，1 已确认，2 已发货，3 已入库，4 已结算，5 已取消。
4.2 供应商结算
供应商货款一律人民币对公结算，账期默认 30 至 60 天按合同约定；采购单、入库单、质检单、结算单四单匹配并经财务复核后付款。供应商后台与供应商端接口不包含任何 LSC、优惠券字段；合作协议明示供应商与权益体系无关。
4.3 库存与履约
自营库存管理采购入库、销售出库、盘点、库存预警，同时支持 C 端散单与 B 端批量出库；支持供应商代发但商品责任由平台承担。平台承担全部售后与质量责任。
4.4 供应链增值服务
可提供账期管理、对账、质检等增值收费；禁止应收款证券化，禁止任何基于 LSC 或优惠券的金融产品。
第五章 推广奖励体系
5.1 推荐奖励机制
机制内容以 3.7 为准：一级直推、每位被推荐人首单触发一次、按成功推荐人数四档阶梯发放独立优惠券、与 LSC 完全脱钩、券与 LSC 同单互斥。技术实现由独立优惠券服务承接：触发事件经消息队列送达券服务，券服务读取推荐人名下已成功推荐人数确定档位（1、2、3、4 及以后），按对应券模板发券；幂等键为推荐关系加被推荐人首单号，并以推荐关系表 first_order_triggered 防重。
5.2 合规底线
零入门费、零多级分佣、零团队业绩奖、零资金返还；优惠券为平台自营营销折让，不涉及向用户支付资金，不形成任何层级计酬关系。
第六章 风控体系
6.1 基础固定风控规则
1 小时内下单超过 10 笔触发人工复核；同一收货地址或设备当日关联 5 个以上新账户预警；大额高频 LSC 抵扣异常复核；1 小时内 3 个以上不同城市 IP 登录复核。
6.2 B 端商户专项风控
资质准入核验（执照真伪、经营状态、法人信息，AI 初审加人工复核）；采购行为监测（批量下单、跨区域收货、短期大额采购）；窜货监测（收货区域分布、采购频次、下游线索）；采购门槛（最低起订量、月度采购频次）。处置措施为取消 B 端资格、冻结权益、终止合作，所有处罚性决定按 1.6 规则人工复核并开放申诉。
6.3 AI 智能风控
防套利风控 Agent 与窜货风险识别 Agent 开关独立、默认关闭；开启后识别批量注册、刷单拆分、薅券套利、虚假商户、窜货风险。AI 仅做标记与建议，高风险处置经人工终审。
第七章 技术架构
7.1 总体架构
中心化高可用微服务架构，集成持牌支付收单、双云对象存储、消息推送；AI 服务集群按需部署。一期务实起步：单库逻辑分表或 4 至 8 物理分片，监控驱动扩容到 32 分片。
7.2 分片策略
权益流水、Grant Lot、Available Lot、订单均按 user_id 或 consumer_id 分片；一期 4 至 8 片，预留 32 片扩容（8 物理库乘 4 逻辑表，取模 32）。跨分片事务采用 Seata AT。
7.3 微服务模块
包含用户服务、权益账本服务（批次账本与释放）、释放计算服务、订单服务、商品服务、供应链采购结算服务、营销服务、优惠券服务（V7.7.1 新增，独立券模板/账户/流水/过期任务）、权益追偿服务（V7.7.1 新增，管理 clawback 与 recovery_pending）、风控服务、对账服务、消息服务、平台管理后台、供应商端、AI 网关（预留）。
7.4 API 限流
通用接口单 IP 每秒 200 请求；核心账务接口（权益增减、券核销、支付回调）单 IP 每秒 50 请求；配置突发熔断与降级。
7.5 技术选型
Java 17、Spring Boot 3、Spring Cloud；MySQL 8.0 分片；Redis 7.0 集群；RabbitMQ 持久化加手动 ACK；XXL-JOB（释放、券过期、权益作废、追偿冲抵、日终对账）；Seata AT；Docker 加 Kubernetes；Prometheus、Grafana、ELK；阿里云 OSS 加腾讯云 COS 双备份；微信小程序；Vue 3 加 Element Plus。AI 启用时引入 Spring AI、LangChain4j、Python、PyTorch。
第八章 数据库设计
全部权益数量字段以 unit 整数存储；金额字段为人民币 decimal(18,2)。以下为表清单与字段定义，共 22 张表。
8.1 用户表 user：user_id 为 bigint 主键；user_type 为 tinyint（0 未认证，1 B 端，2 C 端）；mobile 为 varchar(20) 唯一；is_verified 为 tinyint；referrer_id 为 bigint 可空；nickname 为 varchar(64)；status 为 tinyint；business_license_no 为 varchar(64)；business_audit_status 为 tinyint；audit_time 为 datetime(3)；audit_operator 为 varchar(64)；created_at 为 datetime(3)。
8.2 LSC 账户表 lsc_account：user_id 为 bigint 主键；total_locked_unit 为 bigint 默认 0；total_available_unit 为 bigint 默认 0；total_frozen_unit 为 bigint 默认 0；version 为 int 默认 1；updated_at 为 datetime(3)。本表仅为聚合快照，不含批次字段。

第九章 合规设计
9.1 合规底线落实
1.7 十二条与第三、四、五章规则在接口层与定时任务中强制实现，合规巡检每日自动执行 R01 至 R12 检查，异常即告警并阻断交易；所有硬常量编译锁定，fail-closed 字段守卫递归扫描全部对外响应。
9.2 宣传口径规范
对外允许使用消费回馈、赠送、抵扣、优惠、自营兑换、商户采购价、批量供货；禁止使用发行、锚定、保本、回报、收益、增值、投资、资产、变现、提现、兑付、资金池、返现、进货价、进销差、利润率、算法释放等词汇；B 端招商与 C 端宣传渠道分开投放，不混合对比 B/C 价格。
9.3 财税与财务确认
B 端商户按订单实付金额开具增值税专用发票；C 端消费者按实付金额开具增值税普通发票；LSC 核销与优惠券核销按销售折让规则处理，冲减销售收入。
LSC 赠送环节、释放环节、核销环节与优惠券发放、核销环节各自的会计确认时点与科目，不采用技术方案中的单方表述；上线前必须取得注册会计师出具的书面账务处理意见，开发与财务系统按意见书配置入账规则并冻结参数，参数变更需财务负责人与超级管理员双签。月度按账面与权益流水、券流水核对。
9.4 用户协议与 B 端采购合同
C 端用户协议、隐私政策、权益规则明示并单独确认，完整告知动态释放机制（含速率范围、周期不固定）、混合支付与优惠券不产生权益、优惠券与 LSC 同单互斥、有效期、扣回与追偿规则。B 端购销协议含禁止跨区域窜货、禁止低于建议零售价销售、违规取消资格与冻结权益、采购门槛等条款；外部合作方（含宏博）另签书面合作协议，明确不进入权益与资金清分。
9.5 备案清单
ICP 备案或相应许可、公安联网备案、小程序备案、网络安全等级保护测评（二级或三级）；持牌支付机构收单，平台不从事支付业务；各 AI Agent 启用前分别完成算法备案与安全评估。
9.6 消费者权益保护
落实七日无理由退货与三包；个人信息处理遵循最小必要、单独同意、可删除、可注销；自动化决策提供人工复核与申诉入口，时限按 1.6 执行。
